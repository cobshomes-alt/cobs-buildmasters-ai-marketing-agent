## What is not implemented or not yet verified

- **Milestone 2 multi-source export:** no combined MP4, transition engine, rendered combined preview or multi-source job submission yet. The timeline displays real hard-cut composition and explicitly states this limit. The earlier real single-source output must not be presented as proof of a multi-source export.
- **Milestone 3 automatic editing:** no new instruction-to-timeline AI, scene detection, semantic visual understanding, speech analysis or automatic chronology assembly. Existing server-side OpenAI creative planning remains unchanged, with honest sample/manual mode. Nothing here is labelled AI-generated editing.
- **Milestone 4 advanced editing:** no imported audio/music/voice-over tracks, timed subtitles, animated titles, transition properties, speed changes, advanced colour/white balance, opacity/keyframes, photo rotate/straighten/sharpen, JPEG output or generative transformations. Unsupported controls are omitted or described as pending. Single-source audio fades remain working; multi-source fades are not advertised as working controls.
- No waveform generation, proxy-quality selection, persistent generated thumbnails or resumable large-file upload. Native browser previews are not a server thumbnail service. Upload progress is confirmed file count/stage, not byte progress.
- An uncertain **transfer** can require administrator recovery; the app does not blindly allocate a second object or overwrite the first. Lost registration responses have a working safe retry. In-progress batch state lives in memory; navigation is guarded, but closing/crashing the browser can still leave an unregistered object. A future resumable upload/session ledger needs its own review. Keep the browser open while importing.
- Browser video preview cannot guarantee frame-accurate cuts or audio synchronization at every source boundary; saved trim ranges have not yet been probed against every hosted source duration. Multi-source rendering will need ffprobe validation before accepting jobs, silence for silent sources, matching time bases/frame rates and full decoded-output checks.
- Workspace startup still loads/signs all original metadata URLs;12-card display bounds do not solve server-side cursor pagination or storage signing costs. Latest 50 multi-asset projects are listed by the API; large-project-library pagination remains future work.
- Hosted multi-asset save/reopen/upload acceptance, actual member JWT denial and broad real-footage performance remain unverified. Existing historical P1 results remain separate evidence; no new production acceptance records were created.

## Performance evidence and practical limits

The browser fixture contains 20 source metadata items (12 video, 8 photo) and expands to 21 timeline items after a split. Measured runs added 20 items in 3,441–5,040 ms including Playwright click overhead, HTTP mocks and preview loading; this is not a render speed, network benchmark or 20-large-video decode stress test. Latest raw local measurement: `.tools/premium-performance.json`. Only 12 asset cards are visible/page and at most 40 timeline nodes; preview UI time updates are throttled to 20 Hz while native video playback remains browser-controlled. No waveform or expensive image AI processing runs on the browser thread.

Selected files are passed as File objects, not loaded together into database JSON/base64. Transfers are sequential; originals remain separate from output. Existing local FFmpeg source/output/time/retention/budget limits are unchanged. A future five-minute multi-source renderer must receive a separate CPU/disk/bandwidth/timeout budget instead of silently raising the current 30-second single-source limit.
