## Architecture selected before transfers/background processing

- Supabase remains authoritative for company originals and saved project recipes. Use separate versioned Draft records in existing owner-protected `cobs_posts`, one `media_id` foreign key per project and existing `campaign_id`. Hide these internal project records from social-post approval/publishing lists. No production migration is required for the single-asset milestone.
- A local/owner-operated Node 22 worker uses FFmpeg/ffprobe and an operational SQLite queue under ignored `.tools/media-worker/`. Queue state is operational, not a replacement company database. Do not persist JWTs, API keys or signed URLs. Download only after owner authorization and an explicit export request, from the registered private Storage object. Queue only after complete bounded input capture.
- Worker process is independent of the browser/HTTP request. Pending/processing/completed/failed/cancelled jobs, stable idempotency keys, leases, bounded retries and event history are persisted. Test restart/recovery before claiming it works. Export files stay outside public assets and require fresh owner authorization to download. Originals are never overwritten. Owner can manually upload an export as a separate asset through the existing secure Media Library.
- Default bounds: one active render, four active jobs per owner/eight globally, 50 MiB source/output, 30-second output clips, at most ten-minute input, 720p-family output, one FFmpeg thread, 90-second render timeout, bounded probe/read timeouts. Reject oversized/unreadable inputs. Use only local file protocols and shell-free argument arrays.
- Temporary input/output retention: 24 hours after terminal state; operational history/usage retained 31 days. Cleanup must resolve every target inside the private worker root. Cancellation and worker restart must never mark unverified output completed.
- Implemented usage caps: twenty job reservations/day and 1 GiB reserved input per rolling thirty days. Operator configuration may lower these ceilings. Failed transfers conservatively consume the declared reservation too; these are local-worker caps, not an account-wide billing lock. Existing Supabase usage from other features still consumes quota.
- Resource planning estimate: existing Windows owner PC, two CPU cores, 2 GiB free RAM and 4 GiB free disk recommended, including tool installation and temporary data headroom. Processing times depend on input codec and machine; limits are enforced, not speed promises. No continuous worker on Vercel Functions. No new hosted worker or subscription is purchased.
- Cost planning: local FFmpeg has no API charge; electricity, owner-PC availability and existing storage egress remain real costs. At 20 MB/export, fifty unique exports download approximately 1 GB, before previews/uploads. Default quota should retain headroom; never promise Free-plan availability without checking actual project usage. Cloud render hosting and distributed queues await separate cost/authorization review.

## Local operator setup and review

The checked-out app remains on develop/dashboard-media. No package subscription or API key is needed for deterministic rendering. Tested runtime: portable Node22.23.3 and FFmpeg9.0.2. Other operating systems/runtimes are unverified; Windows Arial font is used for deterministic text.

If tools are absent, run `powershell -NoProfile -File scripts/setup-media-tools.ps1` from the repository. This downloads a pinned free Windows build into ignored .tools, verifies the vendor SHA256 and refuses to overwrite different existing binaries. The same archive was downloaded and checked during development; the installer script itself was reviewed, not redundantly redownloaded for a separate installer smoke test. Preserve its GPL/source notices; no binary is included in Git.

In two local PowerShell terminals, prepend the portable Node directory if Node is not already available:

```powershell
$env:Path = "$PWD\.tools\node-v22.23.3-win-x64;$env:Path"
$env:COBS_LOCAL_RENDER_ENABLED = '1'
```

In terminal one run `npm.cmd run media:worker`. In terminal two run the existing app with `npm.cmd run dev -- --hostname 127.0.0.1 --port 3102` (or production build/start). This local flag is not written to production configuration. Optional `COBS_RENDER_DAILY_LIMIT` and `COBS_RENDER_MONTHLY_BYTES` can lower20/day and1GiB/30days; invalid/higher values revert to safe ceilings. Both app and worker must use the same working directory and COBS_RENDER_ROOT if deliberately overridden. Keep private queue files on a protected local account, outside shared/public folders. Never expose this local service directly to the internet.

Open the existing app → Media Studio → select a registered original, name the project and optionally link its campaign → adjust edits → Save editing project → Render saved project → wait for Completed → Download verified export. Save is a real company database write when using hosted credentials; owner review should avoid saving until ready to authorize that acceptance. Queue source capture takes up to30s; after acceptance the browser can close. A stopped worker leaves durable Pending jobs and an honest offline message. Restarting the worker resumes supported queued work. No automatic approval, attachment replacement or publication occurs.

Download output before its24-hour expiry. To retain permanently, upload it as a new file through the existing Media Library, then explicitly select it while editing a post. This new media reference resets approval through existing controls. Original source and watermark JPEG are never overwritten.

## Reliability and security review

- Every Studio HTTP operation calls existing verified-user + database-owner-role authorization. Downloads additionally match job owner and completed/unexpired state. No service-role bypass or production policy edits.
- API reads the saved recipe and media row using the owner's JWT/RLS; a mismatched updated_at returns409. No caller-supplied download URL. Canonical source path, registered MIME/size, HTTPS configured Supabase origin, no redirects, bounded streaming, timeout and exact byte count are checked.
- Secret credentials/JWT/signed URLs are not persisted in jobs, error messages or media metadata. Private files stay under ignored .tools, never public/. Authenticated output response is private,no-store. Local OS access is an additional trust boundary; it is not encrypted at rest by this application.
- FFmpeg uses shell-free argument arrays, allowlisted local media demuxers/protocols, bounded dimensions/duration, one thread, time and output-size limits. Overlay text is read from private files with expression expansion disabled. This is not a hardened OS sandbox for hostile codecs; keep FFmpeg patched and use a restricted worker account before broader upload access.
- SQLite transactions claim work, enforce budgets/idempotency and lease ownership. Heartbeats prevent concurrent workers from claiming a healthy render. Late results after cancellation or lease loss are discarded. Cancel stops delivery/commit; an already running FFmpeg process may consume resources until exit/90s timeout. Never claim instant process termination.
- Only verified dimensions/codecs/duration/output-size and expected audio can mark Completed. Worker/probe/transfer errors remain Failed or bounded Retry, never successful exports.
- Terminal media is cleaned after24h by the running worker; downloads independently enforce expiry. If the worker is off, physical cleanup waits for restart. History and conservative usage reservations persist31days. Queue deletion would reset local budgets; do not treat this as account-wide billing enforcement.
- Job history is operational audit evidence. Existing post approval metadata is retained, but a comprehensive append-only company audit ledger and production job database are still future work.
