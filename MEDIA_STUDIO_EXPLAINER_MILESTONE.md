## Architecture, cost and security review

Reuse the existing owner-only export API and bounded private-media capture, queue, worker, download path and approval boundary. Captioning is deterministic owner-authored text/timing, **not AI or transcription**. No new provider, subscription, hosted project or rendering service is required.

Local FFmpeg rendering consumes CPU/disk/electricity; future hosted captures still consume existing Supabase usage. Existing bounds remain 12 clips, 6 originals, 60 seconds, 50 MiB combined captured originals/output, 100 MiB intermediate budget, capped deadlines/retries and temporary retention. This phase does not increase those bounds or claim verified hosted quota headroom.

Caption text is written into private text files with FFmpeg text expansion disabled. Only validated numeric timing expressions are generated by the worker; owner text never becomes a filter expression, filesystem path or shell command. The original JPEG logo remains unchanged. Timed captions use conservative line wrapping and sit above the logo area; browser preview remains approximate rather than pixel-identical.

## Implemented behavior

- Select a timeline clip → **Timed subtitles** → **Add timed caption** → enter text/start/end times. Up to 12 cues per clip, 1–120 single-line characters each; times are relative to that clip. Cues must be ordered, non-overlapping, at least one 25fps frame (0.04 seconds), and end within the clip.
- New blank/incomplete caption edits remain local drafts. Their validation message stays visible; **Save production and Export combined MP4 remain disabled** until valid. Server and worker validation remain mandatory.
- Static subtitles and timed cues are mutually exclusive, avoiding overlapping duplicate text. Existing static subtitle text is preserved; the owner clears it explicitly before switching. Legacy recipes without captions remain valid.
- Preview displays the active cue at the playhead. Rendering normalizes video timestamps/frame rate before drawing timed text, so low-frame-rate recordings receive correctly timed captions too.
- Splitting clips redistributes caption intervals and shifts second-clip times. Fragments shorter than one frame are omitted; the original document remains available through existing undo history. Invalid caption drafts cannot be split or exported.
- Captioned snapshots use **sequence version 3**. Existing version-2 combined jobs remain supported. The updated worker advertises capability 3; both browser and server reject caption exports on unsupported workers. An older worker rejects the new sequence discriminator rather than silently omitting captions.
- The legacy single-source route rejects timed-caption recipes with an instruction to use the production timeline. Its existing static-subtitle/photo/video functionality remains supported. This avoids silently dropping new cues in an older single-source job.
- Settings reports current module boundaries, actual configuration/worker checks and unavailable external metrics. The scrollable status table has an accessible name, keyboard focus and visible focus treatment. Key presence is not displayed as live provider verification.
